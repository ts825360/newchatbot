# 행사비서 모델 검증

## 2026-11-26 이전 프롬프트 파일럿

GPT-6 Luna에 실제 Responses API 요청을 보냈다. 개인정보 없는 고정 질문, 같은 응답 스키마와 출력 한도를 사용했다. 측정은 브라우저가 아닌 API 왕복과 응답 파싱을 포함한다.

| 항목 | 기존 프롬프트 | 수정 프롬프트 |
| --- | ---: | ---: |
| 공통 질문 기준 통과 | 6/7 | 7/7 |
| 공통 질문 응답 시간 중앙값 | 3.01초 | 2.49초 |
| 공통 질문 입력 토큰 합계 | 8,551 | 10,014 |
| 공통 질문 출력 토큰 합계 | 1,660 | 1,104 |

최종 프롬프트는 공통 7개와 출발 지연 추가 시나리오를 합쳐 8/8을 통과했다. 브라우저는 별도 Docker 컨테이너와 가상 데이터로 확인했다. 전송 확인 전 요청 0건, 동의 후 실제 요청 1건(HTTP 200), 답변 카드 표시 약 3.46초, 새로고침 후 같은 답변 복원을 확인했다. 실제 교회 데이터나 교회 NAS로는 테스트하지 않았다.

### 발견한 문제와 변경

- 회의록 속 무관한 지시를 실행하지는 않았지만 답변에서 지시를 다시 언급했다. 기록 안의 결정·미정을 중심으로 답하고 무관한 지시나 처리 과정을 인용하지 않도록 수정했다.
- 제목·요약·항목이 같은 내용을 반복했다. 제목은 결정, 요약은 근거, 항목은 서로 다른 수치나 행동으로 역할을 분리했다.
- 중간 프롬프트에서 표의 시각 계산과 요약 결론이 뒤집히는 문제를 발견했다. 가장 이른 출발 시각이 마지노선보다 이르거나 같으면 가능하도록 예시를 추가하고, 시각 값뿐 아니라 결론 방향도 검사한다.
- 권한, 전송 확인, 명단·내부 문서 원문의 자동 전송 금지, 제안 승인 조건, API·DB 계약은 이 프롬프트 변경에서 완화하지 않았다.

이 값은 이전 프롬프트를 대상으로 한 작은 표본의 단일 실행 결과이며, 현재 `main`의 성능을 뜻하지 않는다. 응답 시간 개선을 보장하지 않고, 부하·두 명 동시 사용·Sol 대비 품질은 아직 확인하지 않았다. 시간·좌석 계산을 확정에 쓸 때는 사람이 확인하고, 서버 계산 결과가 있다면 이를 우선한다.

## 같은 질문으로 다시 확인

기본 테스트에서는 유료 호출을 하지 않는다. 아래 명령으로 의도적으로 켜면 로컬 `.env.local`의 키로 가상 질문 8개를 현재 프롬프트에 순차 호출한다. 전체 앱의 라우팅·도구 동작이나 위 과거 기준선을 재현하는 검증은 아니다. 테스트 스크립트나 결과 파일에 실제 교회 자료를 추가하지 않는다.

```powershell
$env:ADVISOR_EVAL_RUN = 'candidate'
pnpm exec vitest run tests/chat-advisor-live.test.ts
Remove-Item Env:ADVISOR_EVAL_RUN
```

검수 항목: 짧은 일반 응답, 준비 상태의 미확인 구분, 정상·지연 출발 시각, 차량 편별 좌석 계산, 명시 날짜의 제안, 미정 후보의 저장 방지, 회의록 인용 지시 무시. 결과는 Git에서 제외되는 `.local/backend-evidence/advisor-live-candidate.json`에 기록한다.
