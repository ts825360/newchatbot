# 행사비서 이슈 인수인계 로드맵

## 목적과 확인 범위

한 건의 실제 행사를 생성해 설문, 장소, 일정, 준비, 차량·숙소 배정, 최종 계획서, 종료 기록까지 운영하고, 다음 행사에서 확인된 경험을 활용하는 것이 목표다. 이 문서는 공개 이슈의 요구사항을 코드와 대응시킨 인수인계 초안이다. 실행 승인, 이슈 종료, 배포 또는 기능 검증 결과가 아니다.

- 2026-11-27 기준 `gh api`로 #35~#43 본문 9건(모두 Open), 연관 기존 이슈 #1~#19 본문 19건(Open 15, Closed 4), 관련 댓글 6건(#35 1건, #1 3건, #5·#18 각 1건)을 확인했다. [#35 통합 댓글](https://github.com/ts825360/newchatbot/issues/35#issuecomment-7212802269)은 #36~#43을 후속 작업으로 묶고 **#40 기준선을 프롬프트 변경 전에 측정**하도록 명시한다. 기존 이슈를 대체하거나 완료 처리하지 않으며 구현, 테스트, 사용자 승인은 각각 기록한다.
- **공개 기준:** [`main`의 `7873305`](https://github.com/ts825360/newchatbot/commit/7873305046286590d3fedf8913152b672afd9dcf)는 검토용 소스(rc.14), 확인한 최신 공개 버전 태그는 [`v0.2.0-rc.15`](https://github.com/ts825360/newchatbot/tree/v0.2.0-rc.15)다. [PR #34](https://github.com/ts825360/newchatbot/pull/34)는 Open이고 나머지 공개 PR #20~#33도 열려 있다. `chatgpt/assistant-integration-review`와 `chatgpt/web-connection-verification-20261127`은 `main` 대비 각 진단 문서 한 파일만 추가된 브랜치로, 제품 감사나 통합 완료 근거가 아니다.
- **로컬 기준:** `codex/google-connection-diagnostics` HEAD [`7775593`](https://github.com/ts825360/newchatbot/commit/7775593eb44832fb714e9bf743a08d280c194f0f)는 공개 PR #34와 같다. 아래의 현재 코드 매핑에는 `package.json`이 `0.2.0-rc.25`인 **미커밋 작업 트리**를 포함한다. rc.25 소스 전체가 공개 SHA에 있다고 가정하지 않는다. 작업 재개 시 브랜치·HEAD·버전·차이와 경로별 작업 소유자를 다시 확인한다.
- **증거 해석:** '코드 확인'은 정적 읽기, '기존 검증 기록'은 다른 작업에서 남긴 결과, '제안/검수'는 후속 작업이다. 이번에는 테스트·빌드·브라우저·실 API·NAS·실제 행사 검증을 실행하지 않았다. 개인 정보, 인증값, 운영 DB·로그·원문은 읽기 범위와 산출물에서 제외한다.

## 전체 구조와 재개 순서

아래 화살표는 **제안한 선행 관계**다. 배포됐거나 서로 자동으로 반영된다는 뜻이 아니다.

```text
#35 인수인계 및 코드 감사
  -> #40 현행 기준선 고정
  -> #36 문맥·도구·승인 경계 검증
       -> #37 공동 자료·권한·출처 -> #38 표준 문서
           -> #39 종료 초안·운영진 확정·다음 행사 검색
                -> #41 회계 -> #42 활동 탐색
  -> #43 실험 설계는 #42 전에, 6군 비교·재평가는 #42와 함께
  -> #40 회귀·사용자 승인 -> #35 실제 행사 및 후속 행사 인수 검증
```

1. **기준 고정:** 충돌하는 로컬 작업을 건드리지 않고 검토 대상과 기준선 스냅샷을 합의한다. #40의 합성 입력, 권한, DB 초기 상태, 도구·모델 설정을 먼저 동결한다. 기존 테스트·로그를 기준선으로 그대로 승격하지 않는다.
2. **우선 읽기:** #36의 첫 복합 검수는 준비 누락 또는 타임테이블의 식사 구간 점검처럼 좁은 읽기 작업으로 한다. #37은 공동 가시성과 안전한 게시·철회부터, #38은 그 위에서 설문과 최종 계획서의 구조화 원본부터 진행한다. 양식 검토는 병렬로 할 수 있으나 공유 저장과 출처 검증 없이는 문서 완료로 보지 않는다.
3. **종료 기록 후 확장:** #39의 첫 종료 기록은 사용 가능한 검증 근거로 만들고, #41 회계·#42 활동 데이터가 없으면 본문에서 미확인 또는 미연동으로 표시한다. 두 이슈가 추가되면 승인된 견적, 확인된 지출, 활동 결과를 각각 출처 버전과 연결한다. #42의 결과→예산·일정 반영은 해당 저장 경계와 사용자 승인 뒤에만 연동한다.
4. **실행 검수:** #43에서 조건을 고정한 비교로 탐색 전략을 선택하고 #40으로 회귀를 반복한다. 실제 행사 실행과 다음 행사 검색은 합성 E2E 이후 별도 사용자 검수로 남긴다.

## 이슈별 매핑과 완료 기준

### [#35](https://github.com/ts825360/newchatbot/issues/35) 개발 인수인계·코드 감사

**코드 확인:** [README](../../README.md), [요구사항 추적](../requirements/traceability.md), [AI 로드맵](../assistant-improvement-roadmap.md), [릴리스](../releases.md), [Docker/NAS](../docker-nas-operations.md), `compose*.yaml`과 테스트가 출발점이다. [SQLite 초기화 스키마](../../lib/server/database.ts), [레코드 검증](../../lib/server/record-schema.ts), [인증·권한](../../lib/server/auth.ts), [스코프·기존 레코드 이관](../../lib/server/conversation-scope.ts), [읽기·쓰기/버전](../../lib/server/records.ts)을 함께 읽는다. 스키마 초기화와 기존 레코드 이관 코드의 존재는 모든 업그레이드 경로의 검증을 뜻하지 않는다.

**후속:** 책임 전환(별도 브랜치에서 코드 감사·소단위 수정 → 담당자 실사용 → 피드백 수정)에 앞서 최신 승인 소스 및 SHA, 미완료/재개 조건, 비밀값 없는 설정 예시, 스키마·이관 및 백업·복구, 테스트 근거를 맞춘다. 모델·API·프롬프트 전문은 해당 SHA의 소스와 아래 조립 지점으로 추적한다. 사례별로 변경 파일·이유·실행 및 미실행 시험·가상 입력/기대 결과를 남긴다. 공개 보존은 별도 승인 후 검토하며 미검증 변경의 `main` 병합이나 동시 수정은 하지 않는다. Node 24+·pnpm은 README, Python 차량 계산과 격리 볼륨·백업·설정은 운영 문서를 기준으로 확인한다. 운영 환경 파일, 실제 명단/가족 정보·문서·대화·DB·백업은 공개 인수인계 대상이 아니다.

**완료 게이트:** (1) 최신 승인 SHA와 재개 가능한 인수인계 확보, (2) 기능·권한·보안 감사와 미완료 목록, (3) 전후 비교 및 사용자 피드백을 회귀로 남기는 절차, (4) 행사 생성→설문→장소→일정→준비→배정→계획서→종료 기록 전체 검수, (5) 다음 행사에서 과거 기록 활용 확인. 이번 문서는 (1)·(2)의 일부다.

### [#36](https://github.com/ts825360/newchatbot/issues/36) 프롬프트·맥락·도구

**코드 확인:** [채팅 API](../../app/api/chat/route.ts) → [`handleChat`](../../lib/server/chat.ts)(세션·권한·대화 소유·최신 턴 확인, 제한된 같은 대화 문맥, 외부 전송/이전 AI 답변 참조 동의 분리) → 명시적 로컬 분기 또는 [OpenAI Responses](../../lib/server/chat-openai.ts). `handleChat`이 [공통 역할·판단·표현 지침](../../lib/server/chat-advisor-prompt.ts), 후속 문맥/설문/조건부 장소 지침, 스타일 지침을 조립한다. 모델 경로는 허용된 도구만 순차 호출(최대 3회)하고 [응답 스키마·파서](../../lib/chat-advisor.ts)와 서버 재검증 이후 대화에 저장한다.

- [준비 현황 도구](../../lib/server/chat-preparation-tool.ts)는 기간과 일정·설문·차량·숙소·체크리스트 등 집계, 자료 존재 여부를 읽는다. 자료 내용·과거 기록·예약·예산은 조회하지 않는다. [공개 대표 장소](../../lib/server/chat-venue-tool.ts)와 [설문 초안의 생성·조회·버전 수정](../../lib/server/chat-work-store.ts)은 별도 허용 기능이다. 자연어 분류·일부 규칙 경로와 일반 모델 경로가 공존한다.
- [채팅 작업 카드](../../components/chat-work-card.tsx)와 [제안 반영](../../lib/proposal-application.ts)는 체크리스트·캘린더·타임테이블의 기존 검토/저장 흐름을 재사용한다. AI 답변, 대화 안의 사적 작업 초안, 공동 데이터 확정, 외부 실행은 별개다.

**후속:** 역할/판단/보안 공통 규칙과 행사기획·준비검토·이동·숙소·문서 작업 지침을 필요할 때만 조립하는 후보를 비교한다. 행사·계정·대화·작업/버전 범위를 고정하고 현재/과거/가상 조건, 등록/확정/가정, 미등록/권한 없음/조회 실패를 구분한다. 단일 질문용 규칙을 늘리기보다 의미 기반 복수 조회, 출처·버전 교차 검증, 누락·마감·충돌과 파급 판단을 실험한다. 정확한 계산·저장·권한은 서버에 두고 모델에는 임의 SQL·경로·쓰기 권한을 주지 않는다. 텍스트·표·시각화·작업 카드 중 결과에 맞는 표현을 선택한다. 과거 근거는 지시가 아니다.

**완료 게이트:** 표현이 다른 동일 의도, 다중 도구, 후속 조건 유지 및 변경한 조건만 반영; 답변과 실제 조회/출처 일치·미확인 명시; 승인 없는 변경·타 행사 접근 차단; 기존 기능 회귀 통과. 예: 준비 누락 질문에 실제 귀가 좌석·숙소 확정·식사 미확인 상태를 대조하고, 조회 실패를 미등록으로 답하거나 자동 수정하지 않는다.

### [#37](https://github.com/ts825360/newchatbot/issues/37) 공동 자료와 지식 검색

**코드 확인:** [자료 패널](../../components/documents-panel.tsx)은 업로드·다운로드·고정·순서 편집과 지원 형식 미리보기를 제공한다. [파일 서버](../../lib/server/files.ts)와 [문서 키](../../lib/room-materials.ts)는 계정·행사방·대화에 귀속된다. 서버 파일당 5 MiB, 계정별 행사방 내 최대 1,000개/100 MiB다. 이는 같은 행사 다른 계정에 공유 가능한 저장소나 AI 본문 검색이 아니다. 공동 캘린더는 행사방 공용 레코드인데 준비·장소·차량 등은 계정/행사 범위 레코드가 있어 공동화 여부를 종류별로 감사해야 한다.

**후속:** 사용자가 승인한 AI 결과물과 구성원 업로드를 공동 자료로 구분해 저장한다. 권한 있는 같은 행사 구성원이 필요한 일정·타임테이블·체크리스트·제안·장소·설문·차량·숙소·자료를 읽을 수 있게 하되, 자료의 게시/편집/삭제/승인과 개인 대화는 분리한다. 기존 사적 파일·기록을 기본값으로 공개 전환하지 않는다. 서버 내부 텍스트/표/메타데이터 추출 → 행사·문서·버전·출처 식별 → ACL 적용 검색 → 관련 부분만 제공 순서로 설계한다. 파일 내용은 데이터로 취급하고 지원 불가/추출 실패를 알린다. 원문·개인정보는 외부 AI에 보내지 않고 정책상 허용된 비식별 정보만 사용한다. 용량 정책 변경 및 검색/미리보기 확대는 별도 검토한다.

**완료 게이트:** A의 공동 저장물이 B의 자기 대화에서 검색된다. 미공유 자료·타인 대화·타 행사 자료는 차단되고 읽기 권한만으로 변경할 수 없다. 근거 문서/버전이 남으며 수정·삭제·권한 회수 시 검색 결과가 동기화된다. 문서 내 무관한 지시가 실행되지 않고 외부 요청에 금지 필드·원문이 없는지 검증한다.

### [#38](https://github.com/ts825360/newchatbot/issues/38) 표준 문서·구조화 생성

**코드 확인:** [기본 수련회 설문](../../lib/retreat-survey-template.ts), [설문 복사본·버전](../../lib/server/chat-work-store.ts), [미게시 Google Forms 초안](../../lib/server/google-form-drafts.ts), [차량 CSV](../../lib/transport.ts)와 기존 자료 패널이 있다. 자료에서 파일을 열 수 있다는 사실이 표준 양식 생성·승인·공동 저장을 의미하지 않는다.

**후속:** 초기 유형은 참가 신청 설문(참가/이동/숙박), 행사 기획서(목적/대상/일정/운영), 회의록(논의/결정/이유/미결), 준비물 목록(수량/담당/확보), 예산 계획서(예상/항목), 진행 일정표(시간/프로그램/담당/장소), 차량 배정표(출발/귀가/인원), 숙소 배정표(객실/숙박/추가 침구), 업무 분담표(업무/담당/기한), 최종 행사 계획서(확정 운영 정보), 행사 종합 기록서(과정/결과/문제/개선)다. 행사별 필요한 것부터 선택하고, 기존 설문 분기·출발/귀가 구분·내부 가족 ID 처리 방향을 유지한다.

**완료 게이트:** 담당자가 유형별 고정 필드(유형·행사 ID·작성일·버전·필수 정보·승인 상태), 반고정 목차/표, 자유 서술/분석과 파일 형식을 검토한다. 동일 유형 반복 생성의 필수 항목을 서버가 검증하고 실제 DB·확정 자료에 없는 값은 미확인으로 남긴다. 계획/실제 및 초안/검토/확정이 다르고 승인 전 공동 변경이 없어야 한다. PDF/DOCX 등 채택한 표시 형식과 구조화 데이터는 같은 원본·버전에서 생성돼야 하며 자료 보관과 열람 권한을 대조한다.

### [#39](https://github.com/ts825360/newchatbot/issues/39) 행사 종료 기록·다음 행사 활용

**코드 확인:** [준비 검토](../../lib/server/retreat-preparation.ts), [장소 이력](../../lib/server/retreat-venue-history.ts)은 구현 단서다. 장소 이력은 운영진이 결과 보고서(TXT/MD)에서 이용 장소·연도와 일부 특성을 등록하는 제한된 기능이며, 일반 보고서 보관/검색 권한의 근거가 아니다. [방 변경 알림](../../lib/server/notifications.ts)은 종료 스케줄러가 아니다. 요구사항 추적 HIST-01/02의 종료 기록 및 범용 경험 검색은 후속 설계다.

**후속:** 종료일 도달 → 서버가 일정·자료·설문·체크리스트·확정 배정 및 가능한 회계/활동 수집 → 결정·변경·문제 분석 → 버전 있는 자동 초안 → 운영진이 현장 사실 보완/확정 → 보존·검색. 종료일은 성공·참석·지출의 증거가 아니다. 행사/종료 시점별 중복 방지, 수정 이력, 재시도와 실패·진행 상태를 설계한다. 목차는 (1) 기본 정보 (2) 준비 과정 (3) 주요 결정과 대안 (4) 참가·설문 (5) 차량·이동 (6) 숙소 (7) 프로그램 계획/실제/변경 (8) 예산·지출 차이 (9) 문제와 대응 (10) 잘된 점 (11) 개선점 (12) 다음 권고 (13) 근거 자료로 한다.

**완료 게이트:** 종료 일정 기반 자동 초안과 운영진 확정, 계획/실제/미확인 분리 및 근거 추적, 다음 행사에서 예방 제안, 개인정보·ACL·버전/삭제 동기화를 검증한다. 행사명/유형/시작·종료일/출처·버전으로 찾고 유형·계절을 우선하되 월 이동, 다른 유형의 관련 경험도 고려한다. 예: 객실 부족 기록을 현재 인원·정원·침구와 비교해 확인 항목을 제안한다. 원인이 미확인이면 추정임을 표시하고 이전 방식을 강제하지 않는다. 모델 재학습이 아니라 편집·철회 가능한 검색을 사용한다.

### [#40](https://github.com/ts825360/newchatbot/issues/40) 기준선·회귀 평가와 도입 검증

**기존 검증 기록:** [모델 파일럿](../assistant-pilot-evaluation.md)의 공통 7개 6/7→7/7은 이전 프롬프트의 소규모 실제 호출 기록이다. 현행 모델·도구 통합 기준선은 아니다. [실호출용 테스트](../../tests/chat-advisor-live.test.ts)는 별도 옵트인이고, [서버 채팅 테스트](../../tests/server-chat.test.ts)와 [도구 호출 테스트](../../tests/chat-openai.test.ts)는 모의 검증에 활용할 수 있다. 추적 문서의 rc.25 기록은 Vitest 1,059개 통과, 실 OpenAI 평가 1개 건너뜀, TypeScript·Docker 빌드 통과를 보고한다. 이번 로드맵 작업의 재실행 결과는 아니다.

**완료 게이트:** 재현 가능한 현재 기준선, 같은 조건의 수정 전후, 사용자 피드백에서 만든 회귀 사례, 도입/보류별 이유와 실측을 남긴다. 의도, 후속 문맥, DB 조회·복수 기능 검증, 양식, 권한 및 개인정보, 위험·누락 발견, 미확인 표현을 평가한다. 자동 검증과 사용자 판단, 모의와 실호출, 프롬프트만 바꾼 비교와 전체 통합 비교를 섞지 않는다. 상세 검수는 아래 공통 절차를 따른다.

### [#41](https://github.com/ts825360/newchatbot/issues/41) 행사별 회계

**코드 확인:** [차량 비용 비교](../../lib/transport-comparison.ts)와 [배정 버전](../../lib/transport-versions.ts)은 견적·미확인 및 확정 배정의 참조 후보이지 실제 지출 원장이 아니다. 행사 회계/영수증/엑셀 내보내기 전용 경로는 확인하지 못했다.

**후속:** 전체 예산과 숙소·차량·식사·활동·준비물·기타의 예상/실제/잔액·사용률·초과를 서버가 계산한다. 견적·예약 확정액·실제 지출을 분리하고 미확인 값은 0이 아니다. 승인된 배정/선택 활동 견적을 출처 ID·버전으로 참조하되 후보 비교 비용은 집계에 넣지 않는다. 지출 등록·영수증·수정 이력·열람/변경 권한·엑셀 출력은 별도로 설계한다. 메뉴·양식은 사용자 검토 사항이며 기존 차량·숙소 비교 화면에 회계를 강제하지 않는다. AI는 분석·경고·제안만 하고, 교회 전체 회계·복식부기·세무·헌금·자동 결제는 범위 밖이다.

**완료 게이트:** 합계·잔액·초과와 미확인 계산, 배정 변경·재시도의 중복 집계 방지, 증빙·엑셀·권한·수정 이력, 종료 기록의 예상/실제/차이와 확인된 원인 일치를 검증한다. 다음 행사에는 확정 근거만 재사용한다.

### [#42](https://github.com/ts825360/newchatbot/issues/42) 다중 출처 활동 탐색

**코드 확인:** [주변 식당·관광 웹 검색](../../lib/server/chat-dining.ts), [출처/이동 참고 계산](../../lib/server/chat-travel.ts), [Maps 요청](../../lib/server/google-maps-request.ts)과 [장소 UI](../../components/location-panel.tsx)는 일부 기반이다. 출처 URL을 반환하는 것과 가격·영업·단체 수용·예약을 공식 확인하는 것은 다르다. 실제 키 구성·할당량·API 호출은 이번에 검증하지 않았고, 기존 코드를 다중 출처 활동 에이전트로 보지 않는다.

**후속:** 목적·인원·연령·시간·예산·지역·이동·날씨 → 활동 유형/검색어 다양화 → 복수 출처 → 중복 제거 → 공식 근거 대조 → 필수 조건 필터 → 순위와 이유. 유명 결과에 편중되면 검색어와 출처를 바꾼다. 네이버 블로그는 숨은 후보·후기, YouTube/Shorts는 발굴·현장 정보, TourAPI는 관광·축제·체험, 웹은 신규·공식 정보, Places/공식 사이트는 위치·운영 조건, 과거 기록은 실제 만족·비용·운영 교훈의 후보로 나눈다. 이슈에서는 Instagram 전체 검색을 보류한다. 공유 링크/이미지의 접근 가능한 정보만 확인하고, 실패·비공개 상태를 표시한다. 접근 제한 우회·무단 수집은 하지 않는다.

**검수 제안:** 초기 가중치는 목적 25·단체 적합 20·독창성 20·예산 15·이동/시간 10·후기 신뢰/최신성 10(%). 행사 유형에 맞춰 변경할 수 있고 필수 조건 미충족은 점수와 무관하게 제외한다. 후보마다 허용된 사진, 설명, 비용·시간·수용·위치/이동·확인된 예약 여부, 후기/공식 출처와 확인일, 적합 이유 및 미확인을 표시한다. 채팅/장소 UI를 우선 재사용하며 새 메뉴는 필수가 아니다.

**완료 게이트:** 다양한 후보·중복 제거, 장소/가격/조건 검증과 미확인 표시, SNS 공유 입력·접근 실패 처리, 운영진 승인 뒤 장소·타임테이블·예산에 반영하는 제안과 이동 조건 검토, #43의 비교를 모두 확인한다. 자동 예약·결제나 외부 검색에 명단/개인정보 전송은 금지한다. 키·쿼터·비용·라이선스·저장 정책과 실호출을 점검하고 추가 결제는 별도 승인한다.

| 기준선 (#40) | 커밋·작업 트리 상태, 모델/API와 프롬프트 버전, 도구 목록·권한, 합성 입력·기대/금지 동작·DB 스냅샷, 반복 수·검색 시점·호출량·지연·비용을 기록한다. 프롬프트 단독 비교는 모델/입력/도구를 고정하고 서버 통합 비교는 분리한다. |
| 자동 검수 | 기존 의존성이 준비된 격리 환경에서 `pnpm exec vitest run tests/`와 관련 경로 테스트를 사용한다. 대화 전환, 복수 도구 선택/출력과 출처, ACL·동의 철회, 잘못된 문서 지시, 중복·최신성 충돌, 오류 복구를 확인한다. 승인 전후 DB 차이와 외부 호출 내역을 모의 검증한다. 스키마 검증·서버 합계·정원·각 편의 개인 ID 대조는 코드가 판정한다. 변경 범위에 따라 `pnpm build`와 Python 배정 회귀를 별도 기록한다. |
| 브라우저·사용자 | 두 가상 계정과 두 행사로 승인/취소/저장실패/재시도·대화 전환, 게시 전후 조회를 확인한다. 대상 PC와 좁은 화면에서 검수한다. 자연스러움·쓸모·방문 의향은 사용자 평가다. 실제 행사의 준비와 종료·다음 행사 활용은 별도 승인 아래 검증하며 공개 증거에는 합성 사례나 비식별 집계만 남긴다. |
| 외부 연동 | OpenAI·Google OAuth/Forms/Calendar·Maps, 후속 검색 API는 모의 통과와 실제 동작을 구분한다. 실제 호출·비용·테스트 계정 승인이 없으면 기존 기록만 인용하고 미실행/차단 사유를 남긴다. 추적 문서 EXT-08과 [Google 격리 파일럿](../google-integration-pilot.md)을 참조한다. |

**이 문서 작업에서는 신규 라이브러리 설치·설정 변경·외부 API 호출을 하지 않는다(GitHub 읽기 제외).** 후속에도 기존 TypeScript/SQLite/모의 Vitest와 비식별 구조화 로그/측정을 우선한다. 아래는 승인되지 않은 후보이며 버전·라이선스·운영 정책은 도입 시점에 다시 확인한다.
