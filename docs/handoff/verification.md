## 공개 전 확인

- GitHub가 공개 저장소임을 확인했다. `main` 및 기존 PR과 분리해 새 개발 브랜치만 게시한다. GitHub 자체 secret scanning은 API에서 비활성 상태로 확인했다. 서버 측 스캐너 검사를 통과했다고 표현하지 않는다.
- 로컬 Git 참조의 텍스트 객체 이력과 공개 후보 인덱스에서 알려진 키·토큰·개인키 형식, 제한 경로, 로컬 환경설정에 있던 비밀값의 정확한 일치를 검사했다. 값은 출력하지 않았다. 후보에서 나온 전화번호 경보는 개인정보 차단을 검증하는 합성 테스트였다. 이 검사는 임의 개인정보·이전 교체된 비밀값까지 모두 찾는 전수 보안 감사가 아니다.
- 로컬 지원 UI/테스트·비공개 자동 스냅샷에는 개인 문의 이메일이 있었다. 실제 주소는 공개 후보와 확인한 원격 브랜치 이력 및 공개 후보의 부모 이력에서 발견하지 않았다. 원본은 로컬에만 보존했다. 공개본에는 설정 가능한 공개 문의 이메일과 가상 테스트 주소만 있다. 개인 연락처 값, 이력 재작성, 인증 정보 폐기는 포함하지 않았다.
- `.env*` 파일, 로컬 실험/기록, 캡처, 명단, 백업·운영 SQLite, 인증 로그를 게시 후보에 포함하지 않았다. 환경설정 예시는 `config/local.env.example`로 분리했다. 화면이나 운영 데이터를 GitHub에 미리 올려서 검사하지 않았다. 브라우저 캡처는 합성 데이터로 만들었지만 이 인수인계에는 커밋하지 않았다.

## 로컬 보존·재개

원래 작업 브랜치와 이전 로컬 커밋을 그대로 두었다. 로컬 참조 번들과 변경 전 문의 설정/테스트 원본, 합성 검증 캡처 및 이전 실험은 Git 무시 대상인 `.local` 아래에 남긴다. 참조 번들은 운영 DB 백업이 아니다. `next-env.d.ts`의 로컬 모드별 자동 생성 경로 차이는 유지했지만 인수인계 커밋에서는 제외했다. 인수자는 공개 브랜치를 clone한 뒤 [인수인계](../development-handoff.md) 순서대로 시작한다. 개인 `.local` 기록이 없으면 없는 자료를 추정하지 말고 공개 테스트와 새 합성 평가 입력을 사용한다.
