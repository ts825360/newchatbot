# 행사비서 AI 개선 로드맵

## 범위와 고정 원칙

서버는 인증, 조회 권한, 사실 확인, 계산, 개인정보 보호와 변경 승인을 책임진다. 모델은 주어진 근거를 해석하고 대안을 설명한다. 요청에서 가정한 조건은 해당 요청에만 적용한다. 대화 중 정한 조건은 같은 개인 대화에만 이어진다. 행사방 기록과 계정 설정은 기존 저장 기능, 권한 및 승인 절차를 거쳐서만 변경한다. 저장됨은 확정됨을 뜻하지 않는다.

외부 검색은 사용자가 방문일을 지정하거나 ‘행사 첫날’처럼 행사 일정 기준을 요청했을 때만 해당 날짜를 사용한다. 날짜를 재확인할 수 없는 경우 미정으로 둔다. 특정 답장에 직접 답할 때는 자동으로 최근 주제의 문맥을 섞지 않는다.

주변 검색에는 참가자 명단이나 내부 자료 대신 허용된 구조화 필드만 보낸다. 진행 중인 검색의 모호한 후속 질문은 기존 외부 채팅 동의 범위에서 별도 해석을 거치며, 검색에는 검증한 조건만 전달한다. 등록 인원은 기존 조회 권한으로 집계하되, 외부 검색에는 인원 구간만 보낸다. 공통 조건 모델은 출처와 적용 범위를 기록하지만 저장된 행사 기록을 변경하지 않는다. 검색 링크는 출처를 나타낼 뿐 개별 사실의 독립 검증을 뜻하지 않는다. 일정 조건에 공통 모델을 재사용하는 테스트는 있으며, 실제 타임테이블 조회 연동과 개별 사실 검증은 이후 단계다.

| 단계 | 공식 범위 | 완료 기준 |
| --- | --- | --- |
| 1 | 대화 문맥 및 조건 관리 | 새 요청·수정·보충·참조·취소를 구분하고, 같은 대화에서 필요한 정보만 이어받는다. 외부 전송 동의, 격리, 승인 정책을 유지한다. |
| 2 | 기존 기능과 AI의 복합 연동 | 서버가 허용된 최신 읽기 모델만 제공한다. 첫 사례는 타임테이블의 식사 시간 검토다. 조회와 변경을 분리한다. |
| 3 | 공통 판단 원칙 및 전문 프롬프트 | 아래 10개 원칙을 기존 지침과 항목별로 대조해 충족·보완·충돌·서버 구현 필요를 표시한다. 중복을 제거하고 전문 규칙을 보존한다. |
| 4 | 표현 및 개인 맞춤 설정 | 질문 유형별로 문단, 목록, 계획 카드를 구분한다. 파서와 UI 호환성, 개인 설정의 적용 범위 및 전송 제한을 검증한다. |
| 5 | 종합 성능 비교 | 동일한 모델·입력·도구 범위에서 프롬프트만 바꾼 비교와 서버 통합 비교를 분리한다. 품질, 문맥 유지, 도구 선택, 사실 정확성, 개입 횟수, API 비용을 평가한다. |

## 최종 판단 원칙과 평가 기준

1. **전체 최적화.** 장소, 일정, 인원, 비용, 이동, 피로도, 안전, 담당자 부담을 행사 목적에 비춰 판단한다. 필수와 선호를 분리하고, 한 지표만 좋아 전체에 부적합한 선택을 피하는지 평가한다.
2. **변경의 연쇄 영향.** 인원이나 장소가 바뀌면 영향을 받는 배정, 식사, 이동, 일정, 비용을 골라 재검토한다. 무관한 조건은 보존하고 승인 없이 데이터를 변경하지 않는지 평가한다.
3. **정보 상태와 최신성.** 저장, 확정, 후보, 예상, 미확인, 재확인 필요, 충돌을 구분한다. 임시 가정을 확정으로 보지 않고, 적용 시점과 조건이 바뀌면 해당 정보만 갱신하는지 평가한다.
4. **행사 단계.** 기획은 후보 비교, 준비는 실행 가능성, 최종 점검은 예약·안전·충돌, 진행 중에는 신속한 대안, 종료 후에는 정산·기록·회고를 우선한다. 단계 미확인 시 단정하지 않는지 평가한다.
5. **독립적·비판적 판단.** 동의나 반대를 위한 동의·반대를 피한다. 사용자의 목적과 전제를 보존하며 문제에는 근거와 대안을 제시하고 근거가 충분하면 한 가지를 명확히 추천하는지 평가한다.
6. **개입과 재작업 최소화.** 조회 가능한 정보는 묻지 않고 가능한 작업부터 한다. 중요한 누락과 확인 방법만 안내하며, 비용 절약으로 필요한 분석을 생략하지 않는지 평가한다.
7. **위험과 업무 우선순위.** 안전, 승인, 참가자 보호, 정원, 예약, 마감 및 다른 작업을 막는 선행 항목을 먼저 확인한다. 상황 근거 없이 고정 점수를 만들거나 핵심 작업을 지연시키지 않는지 평가한다.
8. **피드백과 범위.** 수정 이유를 활용하고 기존의 잘된 요소와 변경하지 않은 조건을 보존한다. 요청·대화·행사·개인 설정 범위를 구분하며, 저장하지 않은 선호를 영구 저장했다고 말하지 않는지 평가한다.
9. **표현 적응.** 일반 질문, 비교, 일정, 설명의 형식을 목적에 맞춘다. 기존 편집 기능으로 연결하고 중복 구현하지 않는다. 출력 검증과 UI가 지원하지 않는 형식을 성급히 도입하지 않는지 평가한다.
10. **최종 답변 검증.** 요청 해결, 조건 유지, 도구와 정보 활용, 사실·추론과 확정·제안 구분, 수치·단위·날짜 일관성, 위험·누락, 불필요한 개입, 미실행 작업, 개인정보와 권한을 확인한다. 점검 과정을 반복 노출하지 않는지 평가한다.

## 검증 방식

같은 멀티턴 대화 묶음으로 조건 수정, 행사 이동, 대표 장소 변경, 날짜 미정, 요청 취소, 권한 없음, 개인정보 포함, 승인 없는 캘린더 반영 요청까지 비교한다. 각 변경이 프롬프트·서버·둘 모두 중 어디에 속하는지 기록한다. 모델이 요청한 조회는 서버가 검증하며, 내부 전용 원문은 모델에 보내지 않는다. 실제 모델로 측정한 성능과 모의 응답으로 검증한 동작은 따로 보고한다.
