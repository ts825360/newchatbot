# 행사비서 AI 통합 구현 순서

`v0.2.0-rc.1`은 현재 기능의 기준 버전이다. 아래 단계는 계획이며 기준 버전에 포함되지 않는다. 각 단계는 별도 변경으로 검토하고 테스트한 뒤 [릴리스 절차](../../releases.md)를 따른다.

## 1. 조회 실행기와 첫 도구

- `lib/server/chat-openai.ts`의 Responses API 전송 및 오류 매핑을 재사용한다. 일반 답변, 도구 호출, 도구 결과를 구분하는 제한된 실행기를 추가하고 기능 플래그 아래 연결한다. 기존 내부 준비 현황 경로는 남겨 둔다.
- 도구 등록부에서 이름, 엄격한 입력 검증, 권한, 전송 가능한 결과를 정의한다. 요청에서 검증한 계정·방·대화 범위를 실행기가 넘기며 모델이 이 범위를 지정하거나 변경하지 못하게 한다.
- `lib/server/preparation-status.ts`, `lib/conversation-places.ts`, `lib/timetable.ts`의 조회·파싱 로직을 재사용해 장소, 일정, 타임테이블, 준비 현황을 연결한다. 원시 DB 행은 모델에 전달하지 않는다. 성공과 실패는 서버가 기록하고 사용자는 근거와 기존 화면 링크를 확인한다.
- 초기 제한은 도구 2회, 모델 3요청, 전체 25초를 후보로 삼는다. 호출 누계와 입출력 크기를 검증한다. 도구 또는 API가 실패해도 기존 수동 기능은 동작해야 한다.

## 2. 명시적 참조와 대화 문맥

- `components/chat-panel.tsx`에서 `@장소`, `@일정`, `@자료`를 선택할 수 있게 한다. 장소에 안정적인 ID를 추가하고 이전 저장 형식을 읽는 호환 로직을 검증한다. 참조 해석 시 권한과 삭제 여부를 다시 확인한다.
- `lib/conversation-store.ts`의 개인 대화 경계를 유지한다. 현재 대화의 최근 요청·참조·결정을 먼저 복원하고 장소 조회의 첫 검증에 후속 질문을 포함한다. 다른 대화는 사용자가 선택한 같은 계정·행사방 범위로 제한한다. 최신 저장 정보가 기억보다 우선하며 전체 대화 원문을 자동 전송하지 않는다.
- 컨텍스트 미터에는 대화 전체 길이가 아니라 외부 전송에 쓰는 대화 문맥의 토큰 추정치와 앱이 정한 예산을 표시한다. `컨텍스트 압축`은 이전 문맥을 요약본으로 대체하되 최근 문답, 내부 데이터 참조와 대화 원문은 보존한다. 내부 전용 메시지와 개인정보는 외부 요약 입력에도 넣지 않는다. 요약은 최신 DB 기록이나 완료 승인 근거로 쓰지 않는다.

## 3. 조회 확대와 기존 기능에 초안 전달

- 설문은 집계, 차량·숙소는 현재 저장 상태와 기존 계산 결과, 자료는 허용된 메타데이터, 과거 행사는 공개된 보고서 항목부터 조회한다. 이름·연락처·원본 첨부파일은 전달하지 않는다. 외부 검색 없이 실제 검색 결과를 주장하지 않는다.
- `lib/chat-advisor.ts`와 `lib/proposal-application.ts`의 일정·체크리스트 흐름을 보존한다. 타임테이블 초안은 `components/workspace-timetable.tsx`에서 검토·수정하도록 연결한다. 승인 전 확정 데이터를 건드리지 않고, 승인 시 권한·기록 버전을 재확인한다.
- 전체 준비도 재산정과 가중치는 조회 연결과 별도로 검토한다. 차량·숙소 계산기는 GPT로 대체하지 않는다.

## 단계별 통과 기준

- 모의 API: 자연어에서 조회, 다른 방과 다른 계정 차단, 개인정보 비전송, 저장 자료 속 지시문 무시, 최신 자료 반영, 제한 초과, 승인 거절과 중복 승인, 실패 시 수동 기능 유지.
- 격리 브라우저: 장소 등록·변경 후 동일한 질문, 이전 장소 참조가 있는 후속 질문, 타임테이블 초안의 편집·승인과 저장 내용을 확인한다.
- 실제 API: 별도 승인 후 합성 데이터만으로 모델별 Function Calling과 결과 반송을 시험한다. 운영 자료로 시험하지 않는다.
