# Google 연동 실검증

로컬 시험 콜백은 `http://127.0.0.1:3020/api/integrations/google/callback`이다. 접속한 앱의 출처, `APP_BASE_URL`과 콜백의 스킴·호스트·포트가 일치해야 한다. `localhost`와 `127.0.0.1`을 섞지 않는다. 운영 주소가 확정되면 별도 HTTPS 콜백을 추가하고 기존 콜백은 유지한다.

1. Cloud 콘솔에서 현재 웹 애플리케이션 OAuth 클라이언트의 승인된 리디렉션 URI에 해당 로컬 주소가 있는지 확인한다. 없으면 기존 주소는 삭제하지 않고 추가한다. 테스트 모드라면 전용 Google 시험 계정이 테스트 사용자에 등록되어 있는지, Calendar와 Forms API가 활성화되어 있는지 확인한다. [Google OAuth 안내](https://developers.google.com/identity/protocols/oauth2/web-server#uri-validation)
2. 운영 데이터를 읽지 않는 별도 시험 볼륨으로 실행한다. 기존 앱이 3020번 포트를 사용 중이면 점검 시간에 시험 앱으로 전환하거나, 프로젝트 관리자 승인을 받아 별도 시험 포트의 콜백을 등록한다. 기존 확정 일정이 있는 볼륨에 시험 계정을 연결하지 않는다.
3. 환경설정 → 보안 및 개인정보 → Google 계정 연결에서 시험 사용자가 직접 로그인하고 적용할 권한을 선택한다. 연결 상태와 연결 테스트를 세 기능별로 확인한다. 토큰이나 인증 코드, 계정의 개인 정보는 기록하지 않는다.
4. 합성 참가 설문 초안을 승인하고 Google 편집 화면에서 미게시 상태, 문항, 필수 여부, 참석 분기 및 선택지를 대조한다. 응답 가져오기는 별도의 접근 제한 시험 설문에 가상 응답 1건을 제출해 확인한다. 미게시 초안은 응답을 받지 않는다. [Google Forms 게시 상태 안내](https://developers.google.com/workspace/forms/api/guides/publish-form)
5. 합성 공동 일정을 하나 확정하고 운영용이 아닌 시험 Google 캘린더에서 제목, 날짜, 시간, 중복 여부를 확인한다. 시험 앱에서 연결을 해제한 뒤 다시 연결하고, 각 기능 상태 및 중복 방지를 재확인한다.
6. 교회 서버에는 HTTPS 주소, 그 주소와 일치하는 OAuth 콜백, Google 오버레이와 비공개 환경 파일이 별도로 필요하다. 기존 DB 데이터를 보호하고 운영용 콜백이나 Google 계정은 사전 승인 없이 바꾸지 않는다.
